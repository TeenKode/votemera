# Votemera — Вотемера

**Мера общего мнения.** Локальная система интерактивного голосования для педсоветов, конференций, семинаров и других мероприятий. Версия 0.4.0.

## Возможности

- Сенсорный терминал `/vote`: 2–6 больших кнопок, один ответ за подход, сообщение о приёме и автоматический возврат к голосованию.
- Экран `/display`: цветные шкалы, числа, проценты, сравнение этапов и изменение долей в процентных пунктах. Обновления через Server-Sent Events (SSE), проверка состояния на сервере каждые 400 мс, автоматическое переподключение.
- `/admin`: создание и выбор мероприятий, до 12 этапов на мероприятие, до 12 вопросов, отдельные названия и цвета вариантов для каждого; открытие, закрытие, скрытие результатов, сравнение, очистка закрытого этапа с подтверждением, CSV-экспорт.
- Настройки: светлая/тёмная тема, название, подзаголовок, акцентный цвет, общая/раздельная шкала, отображение количества и процентов, пауза между голосами и сообщение благодарности.
- SQLite с WAL, транзакции, защита от повторной отправки одного запроса, защита от записи в уже сменившийся этап. Терминал не получает текущие результаты по своему обычному API.
- Встроенное демонстрационное мероприятие «Педагогический совет» (без голосов). Изначально закрыто.
- Без CDN, внешних шрифтов, облачных сервисов, Docker и регистрации участников. После установки интернет не нужен.

## Установка на Proxmox

Создайте непривилегированный Debian 13 LXC: 1 vCPU, 512 МБ–1 ГБ RAM, 4–8 ГБ диска, сетевой мост в локальную сеть, статический IP или DHCP reservation. Установку выполняйте **внутри контейнера**, не на хосте Proxmox.

После публикации этого репозитория на GitHub (замените URL на фактический):

```bash
apt-get update && apt-get install -y git
git clone https://github.com/OWNER/votemera.git /opt/votemera
cd /opt/votemera
bash scripts/install.sh
```

Установщик создаёт пользователя `votemera`, виртуальное окружение, конфигурацию с случайными паролем администратора и ключом терминалов, службу systemd с автозапуском, папку данных. В конце выводит оба секрета. Для закрытого репозитория сначала настройте доступ Git через SSH/deploy key. Порт по умолчанию 8080.

| Адрес | Назначение |
|---|---|
| `http://IP:8080/admin` | Администратор |
| `http://IP:8080/vote` | Все ноутбуки-терминалы |
| `http://IP:8080/display` | Компьютер с проектором/телевизором |
| `http://IP:8080/health` | Проверка сервера |

Откройте страницы в актуальном Chrome/Edge/Firefox, нажмите F11 или кнопку полноэкранного режима. На каждом терминале введите ключ один раз за сеанс браузера. Рекомендуется один активный таб голосования на ноутбук. Пароль администратора не вводится на терминалах.

## Сценарий педсовета

1. В `/admin` выберите встроенное мероприятие или создайте своё. Набор вопросов для сравнения должен быть одинаковым во всех этапах, например «Готовы ли вы использовать искусственный интеллект в профессиональной деятельности?». При желании отредактируйте вопрос до сбора голосов.
2. Выберите «До педсовета», режим экрана «Текущий этап», нажмите «Открыть этап».
3. Педагоги нажимают кнопки на сенсорных ноутбуках; экран обновляется автоматически. Не требуется перезагружать страницы.
4. Закройте этап. При выходе выберите «После педсовета» и откройте его. При необходимости включите сравнение уже во время второго этапа.
5. Закройте голосование, включите сравнение этапов и выгрузите CSV. При разных размерах выборок смотрите прежде всего на изменение долей, а не абсолютных чисел.
6. Для репетиции создайте отдельное мероприятие или очистите тестовые голоса на закрытом этапе до начала педсовета.

Можно редактировать мероприятия только при отсутствии голосов и закрытом этапе: это предотвращает изменение смысла исторических ответов. Выбранное мероприятие активируется при открытии или закрытии этапа. Сравнение показывает все этапы и разницу первого и последнего.

## Конфигурация сервера

```bash
nano /etc/votemera/server.env
systemctl restart votemera
```

`VOTEMERA_ADMIN_PASSWORD` — секрет администратора; `VOTEMERA_TERMINAL_KEY` — общий ключ терминалов (пустое значение разрешает голосование всем в сети); `VOTEMERA_DB` — путь к SQLite (для штатного установщика и обновления не меняйте); `VOTEMERA_HOST` — адрес привязки; `VOTEMERA_PORT` — порт.

HTTP по умолчанию подходит только для доверенной/изолированной локальной сети; секреты передаются без шифрования. Ограничьте доступ межсетевым экраном. Для общей сети используйте HTTPS через reverse proxy с доверенным сертификатом. При использовании Nginx отключите буферизацию для `/api/stream` (`proxy_buffering off; proxy_read_timeout 60s; proxy_http_version 1.1;`). Публично в интернет не выставлять без дополнительной защиты. Ключ терминалов не идентифицирует людей и не исключает намеренное повторное голосование; необходим контроль очереди на месте. Система не предназначена для юридически значимых выборов.

## Обновление и резервная копия

```bash
bash /opt/votemera/scripts/update.sh
```

Скрипт допускает только fast-forward Git-обновление с чистым рабочим деревом, останавливает приём голосов, сохраняет копию SQLite, обновляет зависимости, запускает службу и проверяет `/health`. При ошибке пытается откатить коммит и БД. **Запускать между мероприятиями**, не во время голосования. Резервные копии лежат в `/var/backups/votemera/`. Отдельно сохраняйте `/etc/votemera/server.env` в защищённое место.

```bash
systemctl status votemera
journalctl -u votemera -n 100 --no-pager
sqlite3 /var/lib/votemera/votemera.db ".backup '/root/votemera-backup.db'"
```

## Разработка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
export VOTEMERA_ADMIN_PASSWORD='local-development-only'
uvicorn app:app --host 127.0.0.1 --port 8080
python -m pytest -q
```

Для отдельного теста настоящих браузеров используйте `tests/browser_smoke.py` с установленным Playwright и Chromium. Нужна отдельная пустая БД и сервер на порту 8765 с паролем `test-secret` и ключом `test-key`. GitHub Actions проверяет API, синтаксис JS и shell-скриптов.

## Ограничения версии 0.2.0

В один момент активно одно мероприятие и один этап. Хранятся ответы, их время, случайный идентификатор терминала/запроса; ФИО и персональные идентификаторы голосующих не собираются. Повтор одного сетевого запроса не увеличивает счётчик; повторное намеренное голосование того же человека после паузы не определяется. Точное число людей, изменивших ответ, установить невозможно. При падении сети терминал не подтверждает неподтверждённый голос; повторить можно тот же запрос с тем же идентификатором. В случае перезагрузки страницы во время неопределённого запроса следует проверить ситуацию у администратора. Экран отмечает потерю соединения и сохраняет последние результаты до восстановления. Начальная версия не проверена на реальном LXC и физическом сенсорном устройстве. 

## Многовопросные анкеты (0.2.0)

Создайте мероприятие, добавьте до 12 вопросов с помощью кнопки «+ Вопрос», настройте 2–6 вариантов и порядок вопросов. Набор вопросов одинаков для всех этапов. Терминал последовательно показывает вопросы и позволяет вернуться назад или начать заново. После последнего ответа вся анкета сохраняется атомарно; незавершённая анкета не входит в статистику. При смене этапа черновик сбрасывается. Экран `/display` обновляет результаты всех вопросов через SSE, позволяет выбрать один вопрос и сравнивать этапы. CSV содержит строки по каждому вопросу. База версии 0.1.0 мигрирует автоматически, прежние голоса сохраняются. Для резервного копирования используйте штатный скрипт обновления.


## Интерфейсы и конструктор в v0.3.0

- Терминал: крупные плитки или список, пояснение к вопросу, индикатор прогресса, возврат, отдельное подтверждение по настройке вопроса.
- Экран: обзор 1/2/4 вопросов, ручное переключение и автоматическая ротация страниц, крупные счётчики, темы и сравнение этапов.
- Конструктор: копирование и перестановка вопросов, перестановка вариантов, шаблоны ответов, предпросмотр, импорт и экспорт JSON. Вопросы обязательны, одиночный выбор; условное пропускание вопросов пока не поддерживается.

## Перекрёстный анализ

1. Выберите нужное мероприятие и активируйте его этап через управление.
2. В блоке «Перекрёстный анализ» выберите вопрос группировки и другой вопрос для анализа; выберите групповые шкалы либо тепловую таблицу и сохраните пару.
3. В «Экран результатов» выберите «Связь ответов — текущий этап» или «Связь ответов — все этапы» и нажмите «Только режим экрана».
4. На `/display` распределение обновляется автоматически при поступлении каждой завершённой анкеты. Администратор видит предварительный просмотр при загрузке или обновлении панели.

Доли вычисляются внутри каждой группы, а не от общего числа анкет. Группы с нулём участников отображаются без процента. Наибольший наблюдаемый разрыв долей выражен в процентных пунктах; он не доказывает причинность или статистическую значимость. Малочисленные группы интерпретируйте осторожно. Анализ не связывает участников между этапами и не требует имён. В публичный API передаются только агрегаты для разрешённых экранов; скрытие результатов распространяется на перекрёстный анализ.

Миграция добавляет анонимный идентификатор заполненной анкеты. Для предыдущих версий связь восстанавливается по детерминированным nonce каждого ответа с проверкой этапа, терминала и времени записи. Непарные ответы не угадываются и исключаются из перекрёстного анализа, обычные итоги остаются неизменными. CSV по-прежнему экспортирует общие результаты по вопросам, а не перекрёстные таблицы.

Готовый пример анкеты для педсовета: `examples/ai-teachers.json` (импорт в конструкторе). До обновления сделайте резервную копию SQLite. Браузерный сценарий добавлен в GitHub Actions, его прохождение на GitHub ещё предстоит.


## Анимации в v0.4.0

В настройках оформления доступен параметр «Анимации интерфейса»: плавные и выразительные (`full`), минимальные (`subtle`) или выключенные (`off`). По умолчанию выбран первый режим. Настройка передаётся на все подключённые экраны; системное предпочтение `prefers-reduced-motion` всегда имеет приоритет. Старые базы и клиенты совместимы.

- Экран результатов: плавное изменение счётчиков и процентов, ширины шкал, цветовых ячеек перекрёстного анализа и появление карточек при смене страницы. При поступлении голосов текущие элементы обновляются на месте.
- Терминал: короткое появление вопроса и вариантов, визуальная обратная связь при нажатии и выборе, анимация подтверждения. Выбор с подтверждением не пересоздаёт кнопки.
- Администрирование: появление карточек конструктора и диалогов, анимации кнопок, полей и уведомлений.

Анимации не требуют внешних библиотек и не изменяют результаты голосования. На экране числа интерполируются только визуально, после завершения перехода отображается точное значение.

## v0.5.0 — Обслуживание

После установки или перехода с 0.4.0 один раз запустите `sudo bash scripts/install.sh` для регистрации службы обновления. В `/admin` появится блок «Обновление и резервное копирование»: проверка GitHub, установка обновлений при закрытом голосовании, скачивание согласованной SQLite-копии. Обновления выполняются фиксированной системной службой, веб-процесс не получает root-доступа. Поддерживается официальный HTTPS Git-клон ветки main. Журнал: `journalctl -u votemera-update.service`. Экспорт перекрёстной статистики CSV доступен в панели. HTTP в доверенной сети не шифрует пароль; для удалённого доступа используйте HTTPS-прокси.

## v0.6.0 — Надёжность терминалов

Черновик анкеты сохраняется в sessionStorage на текущем терминале, не переносится на другой этап и сбрасывается по настраиваемому тайм-ауту (по умолчанию 90 секунд). Неподтверждённая отправка сохраняет исходный nonce даже после перезагрузки страницы; временные сетевые и серверные ошибки не уничтожают данные. Терминалы отправляют heartbeat; панель показывает количество активных устройств и текущие итоги каждые три секунды, не перерисовывая конструктор анкеты.

## v0.7.0 — Презентация и репетиции

Конструктор экрана позволяет выбрать порядок вопросов и собрать сценарий из текущих результатов, сравнения этапов и перекрёстной аналитики. Включите «Сценарий показа» в управлении мероприятием. Кнопка «Демонстрация» открывает отдельный экран с вымышленными данными, не записывая голоса в базу; «Создать репетицию» копирует анкету и настройки в отдельное мероприятие без результатов, которое можно выбрать в панели. После репетиции вернитесь к исходному мероприятию.
